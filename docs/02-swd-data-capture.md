# 通过 SWD 直接采集运行数据

## 为什么不需要串口回传

STM32 控制程序运行时，会把位置、速度、PWM 和故障状态等信息保存在 RAM 中；定时器当前计数、PWM 比较值等信息位于外设寄存器。

电脑可以通过 DAPLink 和 SWD 读取这些地址。数据是由电脑侧主动读取的，不需要 STM32 调用 `printf`、发送 UART 数据包或连接蓝牙模块。

```text
STM32 正常执行控制程序并更新变量
                   ↑
             SWD 读取内存
                   ↑
电脑脚本 ← OpenOCD ← DAPLink
   ↓
按类型解析 → 时间记录 → JSON / CSV → 分析或绘图
```

## 实现步骤

1. 编译固件，保留与实际烧录版本一致的 ELF 文件。
2. 从 ELF 符号信息确认变量地址；结构体还需确认字段偏移与类型。外设寄存器地址按芯片定义确定。
3. 启动 OpenOCD 并连接 DAPLink，保持 STM32 正常运行。
4. 电脑脚本连接 OpenOCD 的 Tcl RPC 接口，周期性读取需要的内存。
5. 按整数、浮点数或结构体布局解析数据，并记录主机时间。
6. 保存记录，用于计算行程、速度、停止误差或检查故障状态。

## 本工程中的证据

工程的 `vofa/daplink_step_check.py` 展示了 OpenOCD 内存访问方法：连接本机 `127.0.0.1:50001`，用 `read_memory` 读取数据，用 `mww` 写入目标值。端口来自当时的服务配置，不是 OpenOCD 所有安装的固定端口。

它读取 32 位原始数据，再用 Python `struct` 按小端 `float32` 解析。写入目标值前检查 CPU 状态为 `running`，写入后读回校验。该脚本的波形来源仍是蓝牙 TCP 链路，因此它本身属于混合调试脚本。

后续 `monitor-5revs-a250-j800.json` 与对应汇总文件记录了 DAPLink 直接采样的运动测试。字段包括累计位置、目标圈数、速度指令、运行状态、实际编码器测速值、PWM、定时器 CCR 和编码器计数。

既有记录中的一次 5 圈测试得到约 4.9897 圈行程，运动约 2.656 秒，停稳后 PWM 与 CCR 均为零。该结果来自当时的负载和方向，依赖名义编码器参数换算，不能代表所有负载或双向性能。

## OpenOCD 命令示意

以下为命令格式示意，其中占位符必须替换为匹配固件的真实地址和数据，不可原样执行：

```text
read_memory <变量地址> 32 <读取的32位字数>
stm32f1x.cpu curstate
```

仅采样不需要写内存。修改目标值属于另一项控制操作，需要确认变量含义、当前运行模式以及应用是否会覆盖该值；本仓库不提供可直接触发电机动作的写入命令。

## 使用边界

- **地址必须匹配固件**：重新编译后，RAM 布局可能改变，旧脚本中的硬编码地址不可直接沿用。
- **运行中读取不等于同时快照**：多个变量或结构体字段可能在读取期间被更新。严格同步采样可由固件生成带序号的快照或环形缓冲区，再通过 SWD 读取。
- **采样周期由整条链路决定**：探针速度、SWD 时钟、USB、OpenOCD 请求和脚本开销都会影响采样间隔。主机读取时间不等于 MCU 控制周期。
- **避免依赖短暂局部变量**：优化可能消除变量或让其只存在于寄存器中。长期存在的全局或静态状态更便于观察；`volatile` 不能保证多个字段同时一致。
- **外设寄存器要按定义读取**：部分寄存器具有读清除等副作用，不能把所有寄存器都当作普通 RAM 轮询。
- **运行中读取仍有开销**：它适合本工程这类低频状态观察，不代表零干扰或高速实时记录。

## 与蓝牙和 VOFA+ 的分工

| 方式 | 数据由谁提供 | STM32 是否需要遥测发送代码 | 适用场景 |
| --- | --- | --- | --- |
| SWD 直接读取 | 电脑主动读取内存 | 不需要 | 台架调试、检查内部变量、读取寄存器 |
| UART / BLE 遥测 | STM32 主动打包发送 | 需要 | 无线观察、协议化遥测、VOFA+ 波形显示 |

两种方式可以同时存在。选择哪一条链路，应根据是否需要无线连接、采样频率和同步性决定。
